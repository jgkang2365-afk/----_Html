# 예비조사 업무 규칙

이 문서는 예비조사 기능의 장기 기준 문서다. 이후 예비조사 변경은 이 기준과 새 요구의 차이, 영향 범위, 데이터 호환성을 먼저 비교한 뒤 수행한다.

## 1. 역할과 원천 데이터

- 사업장 상세가 실제 업무 입력의 시작점이다. 사용자는 측정예정일, 보고서 담당자, 날짜별 측정 참여자와 다일 일정을 먼저 계획한다.
- 보고서 담당자는 보고서 작성·관리 담당자다. 사업장 단위 원천은 `measurement_target_business.measurer_id`, legacy 일자별 원천은 `daily_staff.measurer_id`다.
- 측정 참여자는 실제 현장 참여자다. 기존 UI의 `조력자` 명칭은 사용하지 않는다. 단일일은 `collaborators`, 다일은 해당 날짜의 `daily_staff.collaborators`가 원천이다.
- 측정 참여자의 배열 순서와 보고서 담당자 포함 여부는 역할을 뜻하지 않는다.
- 측정자, 메인측정자, 공시료 담당자는 같은 역할이다.
- 예비조사자는 페이퍼상 예비조사를 수행하는 사람 또는 조합이며 측정자·측정 참여자·보고서 담당자와 별개다.
- `daily_staff.measurer_id`를 측정자로, `daily_staff.collaborators`를 조력자로 해석하지 않는다. legacy 값에서 메인 역할을 추론하거나 기존 데이터를 자동 변환하지 않는다.

## 2. 사업장 상세와 캘린더

- 상세 모달의 `조력자`는 `측정 참여자`로 표시한다.
- 보고서 담당자를 선택하면 같은 날짜의 측정 참여자에 기본 체크하지만 사용자가 해제하거나 다른 참여자를 추가할 수 있다. 기본값이지 hard constraint가 아니다.
- 상세 모달에서 측정자·공시료 코드·메인/조력 역할을 선택하거나 자동 결정하지 않는다.
- 1일과 다일은 `측정일 + 보고서 담당자 + 측정 참여자`의 같은 의미와 입력 구조를 사용한다.
- 캘린더 이름은 실제 측정 참여자를 표시한다. 보고서 담당자가 참여자에 포함되면 담당자를 먼저 표시하고, 포함되지 않으면 참여자만 표시한다. 순서는 메인측정자를 뜻하지 않는다.
- 캘린더 색상은 기존 보고서 담당자 기준을 유지한다.

## 3. 측정자와 고정 공시료 코드

| 측정자 | 공시료 코드 |
|---|---|
| 이태환 | A |
| 한기문 | B |
| 강종구 | C |
| 이주형 | D |
| 고유빈 | F |
| 김민영 | G |

- 공시료 코드는 사람별 고정이며 같은 날 여러 업체를 맡아도 `C → CC`처럼 변형하지 않는다.
- 예비조사자, 측정 참여자, 보고서 담당자와 측정자를 직접 맞추는 validation이나 자동 편입을 만들지 않는다.
- 실측정자와 측정자가 달라도 정상이다.

## 4. 추천 계산 순서

강한 제약부터 다음 순서로 해결하고 앞 단계 결과를 고정한 뒤 다음 단계를 계산한다.

1. 사업장 구분
2. 예비조사 방식
3. 예비조사 가능일
4. 예비조사자/조합
5. 측정자(공시료) 균등 배정
6. 초과 업체의 측정자 추가 배정
7. 충돌·동선·용량 검증
8. 짧은 추천 사유 생성
9. 사용자 검토
10. 적용

추천 생성은 임시 draft만 만들고 DB를 변경하지 않는다. 사용자가 본 draft를 그대로 apply하며 저장 직전 stale·lock·hard constraint가 달라지면 다른 안을 자동 저장하지 않고 재검토를 요구한다.

## 5. 업체 구분별 날짜와 방식

- 최초실시: 방문 필수, 측정예정일 기준 working day `-3, -4, -5 ...` 순으로 탐색한다.
- 타기관 신규: 방문 필수, `-30, -29 ... -3` 순으로 탐색한 뒤 불가능할 때만 `-31 ... -60`을 검토한다.
- 최초실시·타기관 신규는 비경력자 단독을 금지하고 경력자 단독 또는 경력자+비경력자를 허용한다.
- 기존업체: 유선 기본이다. 이미 같은 날 필수 신규 방문이 있고 동일주소 또는 가까운 동선이며 방문 허용량과 후발 필수방문 여유를 해치지 않을 때만 선택 방문으로 올린다.
- 기존업체 때문에 별도 방문일을 만들지 않는다. 후발 필수방문 업체가 추가되면 기존업체 선택 방문은 유선으로 재조정할 수 있다.
- 휴일·주말은 추천 후보에서 제외한다.

## 6. 조사량과 작성자

- 방문은 경력자 단독 또는 경력자+비경력자 조합 기준 하루 1개가 원칙이고 동선이 명확히 적합할 때 최대 2개까지 자동추천한다.
- 유선은 1인당 하루 최대 3개다.
- 경력자 단독이면 경력자가 페이퍼를 작성하고, 경력자+비경력자 조합이면 비경력자가 작성한다.
- 경력 여부는 `users.is_preliminary_survey_experienced`만 사용하며 입사일 등으로 추론하지 않는다.

## 7. 측정자 균등 배정

- 6명에게 같은 측정일의 업체를 최대한 균등 배정한다. 6개는 `1/1/1/1/1/1`, 8개는 기본적으로 `2/2/1/1/1/1`이다.
- 첫 균등 순환 이후 추가 배정 우선순위는 `동일주소 > 근거리/실제 측정 동선 > 현재 배정수`다.
- 1인 2개까지 자동추천한다. 1인 3개는 자동 확정하지 않고 예비조사 담당자 또는 관리자 승인을 요구한다. 승인 사유 입력은 요구하지 않는다.
- 동일주소 다사업장은 동선 계산에서 묶을 수 있지만 사업장 record, 상태, 측정자·공시료, 찐확정은 업체별로 유지한다.

## 8. 재추천과 상태

- 기본 흐름은 `검색 → 추천 → 확인 → 적용`이다. 예외 시 `업체 선택 → 영향 범위 재추천`을 사용한다.
- 영향 범위는 같은 예비조사일, 같은 조사자/조합, 같은 주소·방문 묶음, 방문·유선 용량, 같은 측정일의 측정자 균등 배정, 기존 2·3건 배정, 후발 필수방문을 포함한다.
- 문제없는 가확정은 minimum-change로 최대한 유지하고 변경안을 사용자에게 보여준 뒤 적용한다.
- 측정일, 다일 일정, 참여자, 보고서 담당자, 사업장 구분, 주소 등 영향값이 바뀌면 기존 계획을 자동 덮어쓰지 않고 `재검토 필요`로 표시한다.
- `measurement_journal` row가 존재하면 찐확정이다. `sequence_number`를 판정 기준으로 사용하지 않으며 일반 추천·재추천·수정을 차단하고 관리자 repair만 허용한다.
- 추천 사유는 `최초실시 · 방문`, `기존업체 · 유선`, `동일주소 묶음`, `측정자 균등배정`, `2건 배정`, `3건 승인 필요`, `재추천`처럼 짧게 표시한다.

## 9. 권한과 자동화

- 관리자 또는 `users.is_preliminary_survey_manager`가 추천·재추천·적용·1인 3건 승인을 수행한다. 서버가 매 요청 권한을 authoritative하게 확인한다.
- 일반 사용자는 조회 중심이다.
- 기존 V2 자동추천 정책은 OFF 상태를 유지한다. 사업장 상세 저장으로 V2 plan을 자동 생성·확정하지 않는다.
- 기존 V2 DB/service/API/audit와 legacy sync를 보존하며 automatic 구형 plan을 새 정책의 정답으로 자동 승인하지 않는다.

## 11. 후속 데이터 정리

구형 V2 데이터는 새 시스템 안정화 전 삭제하지 않는다. 별도 Phase에서 automatic, manual, 실제 사용·확정, 미사용 구형 plan으로 분류해 유지·마이그레이션·archive·삭제 여부를 결정한다.
