# 예비조사 업무 규칙 (Business Rules)

- 문서 성격: 예비조사 관련 UI·API·DB·추천·수정/확정·테스트·마이그레이션·후속 리팩터링의 기준 문서.
- 원칙: **업무 규칙이 원본이고, 코드는 이 문서를 구현한다.**
  - 현재 코드가 이 문서와 다르더라도 현재 코드 동작을 정답으로 쓰지 않는다.
  - 확정된 업무 규칙을 기준으로 작성하며, 현재 구현과 차이는 마지막 “구현 상태” 항목으로 분리한다.
- 이 문서는 코드 설명서가 아니다.

---

## 1. 용어 정의

### 1.1 보고서 담당자

- DB 개념: `measurement_target_business.measurer_id`
- 의미: 보고서 작성·관리 책임자.
  - 실제 측정 참여 여부와 무관
  - 예비조사 참여 여부와 무관
  - 연계측정자와 동일할 수도, 다를 수도 있음
- 금지:
  - 보고서 담당자를 실제 측정자로 자동 추가하지 않는다.
  - 보고서 담당자를 연계측정자로 자동 확정하지 않는다.
  - 보고서 담당자 변경만으로 예비조사 V2 재추천을 발생시키지 않는다.

### 1.2 실제 측정자

- 의미: 실제 현장 측정에 참여하는 사람.
- 판단 기준:
  - 단일 측정일: `collaborators`
  - 다일 측정: `daily_staff`
- 보고서 담당자와 별개 역할이다.

### 1.3 조력자

- 실제 측정에 참여하지만 연계측정자가 아닌 추가 측정 인력.
- 업무량, 사업장 규모, 측정 포인트 수 등에 따라 복수 지정 가능.
- UI에서는 체크박스 방식이 기본.

### 1.4 예비조사자

- 예비조사에 실제 참여하는 사람. 1명 이상 가능.
- 예비조사자 전체가 실제 측정자와 동일할 필요는 없다.

### 1.5 연계측정자

- 예비조사와 실제 측정을 연결하는 핵심 인력. 사업장/측정대상 단위로 **1명만 존재**.
- 기본 DB 개념: `link_measurer_id`
- 연계측정자는 반드시:
  1. 예비조사자 중 한 명이어야 하고
  2. 전체 측정기간 중 최소 하루 실제 측정에 참여해야 한다.
- 보고서 담당자와 동일할 필요는 없다.

## 2. 역할 관계

| 역할 | 동일해야 하는가 |
|---|---|
| 보고서 담당자 = 실제 측정자 | 아니오 |
| 보고서 담당자 = 예비조사자 | 아니오 |
| 보고서 담당자 = 연계측정자 | 아니오 |
| 연계측정자 ∈ 예비조사자 | 반드시 |
| 연계측정자 ∈ 실제 측정자 | 전체 측정기간 중 최소 하루 반드시 |
| 모든 예비조사자 ∈ 실제 측정자 | 아니오 |
| 모든 실제 측정자 ∈ 예비조사자 | 아니오 |

예시:

1. 보고서 담당자 김민영 / 예비조사자 한기문 / 실제 측정 한기문 + 이태환 → 정상 (연계측정자 = 한기문).
2. 보고서 담당자 이태환 / 실제 측정 강종구 + 김민영 / 예비조사 이태환 + 강종구 → 정상 (연계측정자 = 강종구).
3. 보고서 담당자 고유빈 / 예비조사 고유빈 + 한기문 / 실제 측정 김민영 → 연계 없음(예비조사자 전원이 측정에서 제외) → 저장 불가.

---

## 3. 예비조사 단위

- 예비조사는 측정일별이 아니라 **사업장/측정대상 단위로 1회** 수행한다.
- 측정이 여러 날짜에 걸쳐 있어도 예비조사는 한 번이다.

예:

- 예비조사: 07/15 한기문
- 측정:
  - 08/08 한기문 + 김민영
  - 08/09 강종구 + 김민영

→ 정상. 연계측정자 = 한기문. 추가 예비조사 필요 없음.

---

## 4. 사업장 유형별 예비조사 규칙

### 4.1 기존 사업장

- 경력자: 단독 가능
- 비경력자: 단독 가능
- 예비조사 방법: 현장 가능, 유선 가능 (기존 업무 규칙 유지)

### 4.2 최초 측정 사업장

- 경력자: 단독 가능
- 비경력자: 단독 불가
- 허용 예: 경력자 1명 / 경력자 + 비경력자 / 경력자 + 경력자

### 4.3 타기관 측정 후 신규 유입 사업장

- 최초 측정과 동일한 경력 규칙 적용.
- 비경력자 단독 불가. 경력자 단독 가능.

---

## 5. 경력자 조합 규칙

### 경력자 1명

- 정상. 자동 저장 가능.

### 경력자 + 비경력자

- 정상. 자동 저장 가능.

### 경력자 + 경력자

- 허용되는 정상 조합이다 (대형 사업장, 예비조사 업무량이 많음, 1명 수행이 어려운 경우 등).
- **시스템이 임의로 자동 확정하지 않는다. 사용자 확인 후 저장한다.**
- 흐름: 1차 요청 → 확인 필요 응답 → 사용자 확인 → 최종 저장.
- "비경력자가 없어서 대신 경력자 2명" 같은 fallback 개념으로 설명하지 않는다.

---

## 6. 연계측정자 선택 규칙

- 실제 측정 인원을 먼저 정한 후, 그중 한 명을 연계측정자로 선택한다.
- 금지:
  - 연계측정자를 선택했다고 실제 측정자에 자동 추가하지 않는다.
  - 전체 사용자 목록에서 실제 측정 참여 여부와 무관하게 임의 선택하게 하지 않는다.
- 단일 측정일: 연계측정자 후보 = 현재 실제 측정 인원.
- 다일 측정: 연계측정자는 사업장 단위 1명, 특정 날짜에 자동 배치하지 않는다. 전체 측정기간 중 최소 하루 참여하면 된다.

---

## 7. 연계측정자 후보 제안

- 자동 "확정"과 자동 "후보 제안"을 구분한다.
- 허용:
  - 보고서 담당자가 실제 측정 인원에도 포함되어 있으면 후보로 우선 제안
  - 기존 V2 예비조사자와 실제 측정자의 교집합이 정확히 1명이면 후보 제안
- 금지:
  - 후보를 자동 저장
  - 보고서 담당자라는 이유만으로 자동 확정
  - 후보 제안을 위해 실제 측정 인원을 자동 변경

---

## 8. 실제 측정 인원 변경 규칙

- 연계측정자가 지정된 후에는 연계측정자가 실제 측정 인원에서 완전히 빠지는 상태를 허용하지 않는다.
- 단일일: 연계측정자로 지정된 사람은 측정자에서 해제 불가하도록 할 수 있다.
- 다일: 연계측정자가 모든 측정일에서 제거되면 저장 차단.
- 중요: 연계측정자를 특정 날짜, 특히 Day1에 자동 삽입하지 않는다.

---

## 9. 기존 예비조사자와 실제 측정 인원 연결

- 기존 V2 예비조사 계획이 존재할 때 예비조사자 전원이 실제 측정 인원에서 빠지는 상태는 저장할 수 없다.
- 이 경우 사용자는 실제 측정 인원을 조정하거나 예비조사를 재추천/재확정해야 한다.
- 시스템이 임의로 예비조사자를 실제 측정자에 추가해서 해결하면 안 된다.

---

## 10. 예비조사 추천 생명주기

### 단계 1 — 측정대상 등록 / 측정 일정 및 인력 설정

- 측정예정일과 실제 측정 인력이 설정된다.

### 단계 2 — 연계측정자 지정

- 실제 측정 인원 중 한 명을 선택한다.

### 단계 3 — 예비조사 추천

- 사업장 유형, 경력 조건, 일정 조건, 연계측정자 등을 기준으로 추천한다.

### 단계 4 — 사용자 확인/수정

- 예비조사일과 예비조사자를 수정할 수 있다. 조건 위반은 저장 차단.

### 단계 5 — 재추천/교체

- 측정 인력 또는 연계측정자가 변경되어 기존 계획이 유효하지 않으면 재추천할 수 있다.
- 새 계획 확정 시 기존 계획은 교체한다.

### 단계 6 — 실적 확정

- 측정일지에 실제 연번이 부여되면 예비조사 관련 핵심값은 실적 성격으로 본다.
- 일반 사용자 수정 제한. 관리자는 예외 수정 가능.
- 가능하면 관리자 수정 시 수정자·수정 시각·수정 사유 기록을 권장한다.

---

## 11. 계획 데이터와 실적 데이터

- 측정일지 연번 부여 전: 예비조사 V2 = **계획**. 수정/재추천/교체 가능.
- 측정일지 연번 부여 후: **실적에 연결된 사실상 확정 데이터**. 일반 사용자 수정 제한.
- 중요:
  - `preliminary_survey.sequence_number`는 확정 기준으로 사용하지 않는다 (생성/수정/삭제 과정에서 재부여될 수 있어 안정적인 확정 경계가 아님).
  - 확정 경계는 `measurement_journal.sequence_number`를 기준으로 한다.

## 12. 예비조사 추천일 규칙

현재 구현된 V2 추천 날짜 정책을 "현재 정책"으로 기록한다. (이 문서 작성에서 임의 변경하지 않는다.)

- 측정예정일 기준 근무일 역산:
  - 1차 우선 범위: -30 근무일 ~ -20 근무일
  - fallback: -19 근무일 ~ -3 근무일
  - 금지: -2, -1 근무일
  - -30보다 과거로 추가 검색하지 않는다.
  - -3까지 가능한 날짜가 없으면 `manual_required` 상태로 처리한다.
- 이 날짜 정책은 향후 별도 검토/변경 가능한 정책임을 명시한다.

---

## 13. 기존 V2 40건의 의미

- 기존 40건은 정상 운영 과정에서 생성된 데이터가 아니라 **초기 시스템 구축 과정에서 기존 데이터를 역산하여 생성한 초기 V2 데이터**이다.
- 따라서 향후 운영 기준으로 그대로 일반화하지 않는다.
- 최근 READ-ONLY 검증 결과: A 26건 / B 0건 / C 14건 / D 0건.
  - C 14건은 기존 V2 예비조사자와 실제 측정자가 연결되지 않는 사례.
- 운영 DB를 자동 수정하지 않는다. 향후 실제 운영 전 사용자 판단을 거쳐 재설정한다.
- 개별 14개 사업장 목록은 문서 본문에 두지 않고, 필요 시 별도 부록 또는 운영 정비 작업으로 둔다.

## 14. UI 원칙

- 보고서 담당자: 단일 Select.
- 연계측정자: 단일 Select. 실제 측정 참여자 중에서 선택.
- 조력자: 체크박스. 복수 선택 가능.
- 권장 표현: 가능하면 한 영역에서 `보고서 담당자 | 연계측정자 | 조력자`가 쉽게 구분되도록 한다. UI 밀집도가 과도하면 섹션 분리는 허용하되 업무 의미가 섞이면 안 된다.

---

## 15. 시스템 자동화 허용/금지 원칙

### 허용

- 후보 제안
- 조건에 맞는 추천
- 업무 규칙 위반 사전 차단
- 경고
- 사용자 확인 요청

### 금지

- 보고서 담당자 자동 측정자 편입
- 보고서 담당자 자동 연계측정자 확정
- 연계측정자 선택 시 실제 측정자 자동 추가
- 다일 측정 Day1 자동 연계측정자 배정
- 사용자의 인력 선택을 시스템이 임의 변경
- 업무 규칙을 만족시키기 위한 숨겨진 fallback 적용

## 17. 현재 미확정 / 후속 검토 항목

확정된 규칙과 아직 결정되지 않은 규칙을 섞지 않는다. 아래 항목은 **미확정**이다.

- 공정 변경 사업장의 예비조사 규칙
- 추천 날짜 범위 재조정 여부
- 예비조사 정보 통합 UI 상세 설계
- 실제 측정 인원의 최종 source of truth 정규화 여부
- 기존 `daily_staff.measurer_id`의 장기적 역할 정리

이 항목들은 임의로 정책을 결정하지 않는다.

## 19. 문서 연결

- 예비조사 업무 규칙의 기준 문서는 이 문서(`docs/business-rules/preliminary-survey.md`)이다.
- `project_rules.md`의 문서 역할 목록에 이 문서를 참조로 추가했다.
- 같은 업무 규칙을 여러 파일에 복붙하지 않고 원문은 이 파일 한 곳에 유지한다.

---

## 20. 검증 체크리스트

1. 보고서 담당자와 실제 측정자를 혼용하지 않았다.
2. 연계측정자가 사업장 단위 1명으로 정의됐다.
3. 연계측정자의 최소 하루 측정 참여 규칙이 있다.
4. 모든 예비조사자가 측정해야 한다는 잘못된 규칙이 없다.
5. 기존/최초/타기관 신규의 경력 규칙이 구분됐다.
6. 경력자 2명 조합이 정상 조합이며 확인 후 저장임을 명시했다.
7. 단일/다일 측정 규칙이 구분됐다.
8. 보고서 담당자 fallback이 금지됐다.
9. 측정일지 연번(`measurement_journal.sequence_number`)이 확정 경계임을 명시했다.
10. 미확정 사항을 임의로 결정하지 않았다.
