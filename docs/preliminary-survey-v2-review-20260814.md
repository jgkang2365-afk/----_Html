## migration 및 RPC 준비상태

| 점검 | 결과 | 근거 |
|---|---|---|
| V2 테이블 존재 | 정상 | 운영 PostgREST OpenAPI |
| 필수 컬럼 | 정상 | 운영 OpenAPI와 migration 비교 |
| status/plan_origin/survey_method 제약 | 저장소 정의 정상 | migration CHECK 정의; REST에서는 catalog constraint 직접 조회 불가 |
| target unique | 저장소 정의 정상 | `measurement_target_business_id UNIQUE`; REST에서는 index catalog 직접 조회 불가 |
| 날짜/status index | 저장소 정의 정상 | `idx_preliminary_survey_v2_date` |
| created_at/updated_at | 정상 | 운영 OpenAPI |
| RPC 존재 | 정상 | 운영 OpenAPI `/rpc/persist_preliminary_survey_v2_plan` |
| RPC 인자 | 정상 | 운영 OpenAPI와 서비스 호출 비교 |
| 실제 적용 추정 | 정상 | 최신 survey_method 포함 스키마·RPC가 운영에 노출됨 |
| legacy UPDATE 제거 | 정상 | 커밋 8eb7b1c에서 `preliminary_survey.preliminary_surveyor` UPDATE 제거 |

실제 unique/index catalog는 현재 REST 연결로 직접 조회할 수 없어 저장소 migration 정의로 확인했다. 테이블의 최신 컬럼과 RPC 서명이 운영 OpenAPI에 모두 노출되므로 migration 적용 상태는 일치하는 것으로 판단한다.

## 저장 경로 side effect 분석

`/api/preliminary-survey-v2/recommend` → `recommendAndPersistV2` → `calculateV2Recommendations` → `persistV2Recommendations` → `persist_preliminary_survey_v2_plan`

- API는 관리자 세션 확인 후 저장 경로를 호출한다. 이번 검증은 API를 호출하지 않고 `calculateV2Recommendations`만 직접 사용했다.
- 계산 함수는 SELECT와 외부 경로 조회만 수행한다.
- 저장 함수가 호출되면 RPC가 `preliminary_survey_v2_plans` 한 테이블에만 INSERT/UPSERT한다.
- RPC는 source 변경 검증을 위해 `measurement_target_business`를 `FOR UPDATE`로 잠그고 `measurement_journal`을 SELECT하지만 값을 수정하지 않는다.
- 최신 migration에는 `preliminary_survey`, `measurement_target_business`, `measurement_journal` UPDATE가 없다.
- 따라서 저장 시 변경 가능한 테이블은 `preliminary_survey_v2_plans`뿐이며 legacy 측정자·실제측정자·보고서담당·공시료 side effect는 코드상 없다.
