# office-work-ui-ux

## 목적

업무 시스템 UI/UX를 설계·개선할 때 화려함보다 업무 속도와 이해도를 우선하고, 조밀한 정보 구조와 일관된 흐름을 기본값으로 사용한다. 업무 간결성, 흐름성, 정보 밀도, 기존 UI와의 동질성, 실수 방지를 최우선으로 적용한다.

측정일지 웹과 같은 사무형 업무 시스템의 신규 개발·개선·리팩터링·검토에 적용한다. 기존 화면을 한꺼번에 바꾸지 말고, 요청받아 수정하는 화면에 점진적으로 적용한다.

## 적용 절차

1. 사용자가 가장 자주 수행하는 업무와 완료 조건을 확인한다.
2. 동일 프로젝트의 기존 화면, 공통 컴포넌트, spacing·border·radius·typography·color token을 먼저 확인한다.
3. 선택 → 입력 → 검토 → 실행 → 완료 흐름과 데이터 의존 관계를 확인한다.
4. 아래 원칙을 현재 화면에 필요한 범위로 적용한다.
5. 작업 후 검수 항목으로 실제 화면과 상호작용을 확인한다.

## 기본 원칙

### 1. 필터는 최대한 1줄로 구성한다

- 검색, 기간, 담당자, 상태, 구분 필터를 가능하면 한 줄에 배치한다.
- 불가피할 때만 2줄을 사용한다.
- 필터 때문에 테이블 시작 위치가 과도하게 아래로 내려가지 않게 한다.
- 우선순위가 낮은 필터는 접기 또는 더보기에 배치한다.

### 2. 가로스크롤을 최대한 배제한다

- 1280px 이상 일반 사무용 데스크톱 화면에서는 불필요한 가로스크롤이 생기지 않도록 우선 설계한다.
- 업무 중요도에 따라 컬럼 우선순위를 조정한다.
- 불필요한 컬럼은 제거하거나 상세보기로 이동한다.
- 긴 값은 말줄임과 tooltip 또는 column resize를 함께 사용한다.
- 업무상 꼭 필요한 경우에만 가로스크롤을 허용한다.
- 모바일 대응을 이유로 데스크톱 업무 화면의 정보량을 과도하게 줄이지 않는다.

### 3. 상단 여백을 최소화한다

- 제목, 설명, 필터 영역이 화면을 과도하게 차지하지 않게 한다.
- 긴 설명은 도움말, tooltip 또는 접기로 이동한다.
- 가능한 경우 첫 화면에 테이블 헤더와 데이터 일부를 노출한다.

### 4. 테이블 헤더를 고정한다

- 페이지 전체 스크롤인지 테이블 내부 컨테이너 스크롤인지 먼저 확인한다.
- 실제 사용자가 스크롤하는 영역을 기준으로 sticky가 동작하도록 스크롤 컨테이너, overflow, top 값을 설정한다.
- 세로 스크롤 시 헤더를 sticky 처리한다.
- 필요하면 순번, 사업장명 등 핵심 1~2개 컬럼의 좌측 sticky를 검토한다.
- sticky 영역이 겹치지 않도록 z-index와 background를 명확히 지정한다.

### 5. 버튼명은 짧고 함축적으로 작성한다

- `문서 템플릿 등록하기`는 `등록`으로 줄인다.
- `입력 항목 설정`은 `입력 설정`으로 줄인다.
- `사용 상태 중지`는 `사용 중지`로 줄인다.
- `선택한 항목 삭제`는 `삭제`로 줄인다.
- 동일 기능에는 화면마다 같은 업무 용어를 사용한다.

### 6. 말줄임 값의 전체 내용을 확인할 수 있게 한다

- `...` 처리된 값은 hover tooltip으로 전체값을 확인할 수 있게 한다.
- 중요 컬럼은 사용자가 폭을 조절할 수 있도록 검토한다.
- 가능하면 더블클릭 자동맞춤을 고려한다.
- 전체값 확인만을 위해 별도 상세화면에 반드시 들어가야 하는 구조를 피한다.

### 7. 업무 흐름을 한 방향으로 구성한다

- 선택 → 입력 → 검토 → 실행 → 완료 순서로 구성한다.
- 같은 업무에서 화면을 위아래로 반복 이동하지 않게 한다.
- 상위 선택값 변경 시 하위 작업영역을 자동 동기화한다.
- 관련 작업을 다른 메뉴나 탭으로 불필요하게 분산하지 않는다.

### 8. 상태 색상을 통일한다

- 정상·사용 중은 초록을 사용한다.
- 대기·주의는 노랑 또는 주황을 사용한다.
- 오류·삭제는 빨강을 사용한다.
- 선택·주요 액션은 파랑을 사용한다.
- 같은 의미에 화면마다 다른 색을 사용하지 않는다.

### 9. 주요 액션은 한 영역에 1개만 강조한다

- 저장, 등록, 확정 등 현재 단계의 대표 액션 하나만 강조한다.
- 보조 기능은 테두리형 또는 중립 버튼으로 처리한다.
- 한 영역에 파란 Primary 버튼을 여러 개 배치하지 않는다.

### 10. 테이블을 조밀하게 구성한다

- 업무용 테이블에 과도하게 넓은 행 높이를 사용하지 않는다.
- 카드보다 테이블이 적합한 업무에는 테이블을 우선한다.
- 같은 프로젝트 안에서 테이블 밀도를 통일한다.

### 11. 필터·정렬·스크롤 상태를 보존한다

- 상세화면이나 모달 진입 후 복귀해도 가능한 한 검색어, 필터, 정렬, 페이지, 스크롤 위치를 유지한다.
- 사용자가 같은 조건을 반복 입력하게 하지 않는다.

### 12. 빈 상태에 다음 행동을 제공한다

- `데이터 없음`만 표시하지 않는다.
- `2026년 하반기 등록 양식 없음`처럼 현재 상태를 구체적으로 설명한다.
- `등록` 등 사용자가 다음에 수행할 행동을 함께 제공한다.

### 13. 파괴적 기능을 분리한다

- 삭제, 초기화, 사용 중지를 저장이나 등록과 시각적으로 분리한다.
- 삭제에는 빨간색 계열을 사용한다.
- 확인창에 반드시 대상명을 표시한다.
- 가능하면 hard delete보다 사용 중지와 복구 구조를 우선한다.

### 14. 반복업무에는 일괄처리를 검토한다

- 같은 작업을 여러 행에서 반복하면 체크박스와 일괄처리 가능성을 검토한다.
- 사용 빈도가 낮으면 일괄 기능 때문에 UI를 복잡하게 만들지 않는다.

### 15. 모달을 남용하지 않는다

- 간단 확인, 간단 수정, 미리보기에 모달을 사용한다.
- 입력항목이 많거나 스크롤이 길면 본문 패널 또는 별도 화면을 사용한다.
- 중첩 모달을 최대한 금지한다.

### 16. 기존 UI와의 동질성을 우선한다

- 기존 Button, Input, Table, Modal, Card 컴포넌트를 우선 재사용한다.
- 새 화면 하나 때문에 독자적인 디자인 시스템을 만들지 않는다.
- 기존 spacing, border, radius, typography, color token을 우선 사용한다.

### 17. 사용 빈도를 기준으로 기능 우선순위를 정한다

- 자주 쓰는 기능을 바로 노출한다.
- 드물게 쓰는 관리 기능은 더보기나 보조영역으로 이동한다.
- 중요도가 낮은 기능이 화면을 더 많이 차지하지 않게 한다.

### 18. 편집 가능 상태와 읽기 전용 상태를 구분한다

- 사용자가 값의 수정 가능 여부를 고민하지 않게 한다.
- 읽기 전용 값과 입력 필드를 시각적으로 명확히 구분한다.

### 19. 저장 여부를 명확히 한다

- 자동 저장인지 저장 버튼 방식인지 화면마다 일관되게 적용한다.
- 미저장 변경사항이 있으면 이탈 전에 경고한다.
- 저장 성공과 실패 피드백을 즉시 제공한다.

### 20. 판단에 필요한 정보를 함께 배치한다

- 문서 종류를 선택하면 해당 template, mapping, status를 같은 작업 맥락에서 바로 보여준다.
- 서로 연관된 업무 정보를 다른 탭이나 화면에 불필요하게 흩어놓지 않는다.

## 디자인 스타일

- 전체 분위기는 차분한 사무형으로 유지한다.
- 배경은 흰색과 연회색 중심으로 사용한다.
- 주요 액션은 파랑, 정상 상태는 초록, 위험과 삭제는 빨강을 사용한다.
- 과도한 gradient, shadow, 장식을 사용하지 않는다.
- radius와 카드는 최소한의 구획 구분에만 사용한다.
- 디자인 장식보다 업무 정보를 우선한다.

## 작업 전 체크

UI/UX 작업을 시작하기 전에 다음을 확인한다.

1. 이 화면에서 가장 자주 수행되는 업무는 무엇인가?
2. 사용자가 몇 번 클릭해야 업무를 완료하는가?
3. 다른 기존 화면에 동일한 패턴이 있는가?
4. 1280px 이상 일반 사무용 데스크톱 화면에서 불필요한 가로스크롤을 피할 수 있는가?
5. 필터를 한 줄로 줄일 수 있는가?
6. 테이블 상단 공간이 과도하지 않은가?
7. 긴 값의 전체 내용을 확인할 방법이 있는가?
8. 실제 사용자가 스크롤하는 영역을 확인했고, 그 영역에서 테이블 헤더를 잃지 않는가?

## 작업 후 검수

최소한 다음을 확인한다.

- 1280px 이상 일반 사무용 데스크톱 화면의 불필요한 가로스크롤 발생 여부
- 필터 줄 수
- 실제 사용자 스크롤 영역 기준의 테이블 헤더 sticky 동작
- 상단 여백
- 버튼명 길이와 용어 일관성
- 말줄임 값의 tooltip 또는 column resize
- 상태 색상 일관성
- 기존 공통 컴포넌트 재사용 여부
- 선택 → 입력 → 검토 → 실행 → 완료 흐름
- 필터, 정렬, 페이지, 스크롤 상태 보존
- 빈 상태의 다음 행동
- 파괴적 작업 분리

## 대표 예시: 문서 템플릿 관리

다음 흐름을 한 방향으로 구성한다.

문서 종류 선택 → 하단 템플릿 관리 자동 동기화 → 연도·주기·파일 선택 → 누름틀 분석 → 분석 요약 → 매핑 미리보기 → 등록 → 완료

분석 후에는 `총 누름틀`, `고유 누름틀`, `자동 매핑`, `미매핑` 요약을 먼저 보여주고 상세표를 아래에 배치한다. 사용자가 등록 가능 여부와 추가 검토 대상을 먼저 판단한 뒤 상세 내용을 확인하게 한다.
